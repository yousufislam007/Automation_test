# Web explore: community pages B (messages, events wizard, library dialogs, composer, course editor, notifications, profile settings, oddity re-checks)

Site https://sqa.ezycommunity.pro.bd only, explored 2026-11-05 as admin "Team SQA" through the shared CDP browser. `/api/auth/me` returned 200, no 429, no login. Nothing was posted, saved, sent, reacted, toggled, uploaded or deleted. Member names and emails are masked ("Member A", `<email>`). This file only adds what `web-explore-community.md`, `web-explore-events-admin.md` and `web-explore-feed-courses.md` do not cover. Other testers keep posting, so counts and times change.

## 1. /talk (messages)
- `/talk` always redirects to the latest DM: `/talk?dm=<id>`. I did not choose a conversation: the app auto-opened the DM with "Member A" (the one already read by the admin, last message from Team SQA). No other conversation was opened, so no read state changed elsewhere.
- Layout: far-left community rail (two icon buttons + a "+" button), column 2 = list, column 3 = conversation, optional column 4 = side panel (Pinned / Files). Header of column 2: button `Back to community` (arrow), link to `/feeds` "SQA Team / 43 members".
- Three tiles (plain buttons): **Threads**, **Mentions**, **Saved**. Their URLs: `/talk?view=threads`, `/talk?view=mentions`, `/talk?view=saved` (each replaces the list column; the DM list is hidden while a tile view is open). `/talk?view=rooms` is not valid (it redirects to the DM).
  - Threads view: rows "<member> / time / first words / N replies". Mentions view: rows with "mention" text and time. Saved view: saved messages as rows (author, date, text). Not clicked: any row.
  - Mentions tab here is not empty (it has mention rows), unlike the bell notification "Mention" tab which is empty (section 8).
- Two tabs under the tiles: **Direct messages** (default) and **Rooms** (plain `button`, locate with `button:text-is("Rooms")`; `getByRole('button',{name:'Rooms'})` also matches nothing else but fails once a tile view is open because the tabs are replaced).
- Direct messages tab: heading "Direct messages" + icon button `New DM` (aria-label/title "New DM", a "+"). Rows = button with avatar/initials, name, last-message preview, relative time ("17h ago", "5d ago", "2w ago"). 5 DMs at the time. No search box in the list itself.
- `New DM` dialog: title "New direct message", `Close` (x), input placeholder "Search by name…", empty hint "Start typing to search community members." (no list until you type; not typed).
- Rooms tab: sub-filters `All`, `Joined`, `Not joined`; heading "Rooms", `New room` icon button (aria-label "New room"; a second text button "Create a new room" at the end of the list). Rows: emoji tile, room name, "N members" or "Members only · N members", time. Not-joined private room shows a `Request` button (not clicked). 4 rooms: 2 joined public, 1 joined private, 1 private not-joined. Joined filter = 3 rooms, Not joined = 1 room.
- `New room` dialog "Create a room": "Rooms organize conversations by topic. Make it public, private, or paid." TYPE as 3 buttons: **Public** (Open to all, anyone can find and join instantly), **Private** (Listed but locked, must request to join), **Hidden** (Fully invisible, only admins add members). "NAME & TILE": emoji picker button (default a notebook emoji) + input placeholder "e.g. field-notes", TOPIC (optional) input placeholder "What's this room about?". Buttons `Cancel`, `Create room` (disabled while the name is empty), `Close`. The label text "NAME & TILE" and the helper "PICK AN EMOJI, SHAPE, OR IMAGE" run together in the page text (visual nit, only seen in innerText).
- Conversation header (DM): avatar link `View <name>'s profile` (`/profile/<handle>`), name link, subtitle "Direct message", icon buttons `Block <name>` (title and aria-label), `Pinned messages`, `Files` (aria-labels). No call/video buttons.
  - `Pinned messages` opens a right side panel (not a dialog) titled "Pinned": empty state "No pins yet / Pin important messages and they'll show up here." with a close x.
  - `Files` opens a right side panel titled "Files": rows with an icon, file name and sender (a GIF and a .txt), no download button visible.
- Message list: day separators ("YESTERDAY", "FRIDAY, OCTOBER 30"), sender name + time (for the first message of a run), `Load older messages` button at the top, thread summary buttons "3 replies · last reply 23h ago" (opens the thread, not clicked).
- Message hover toolbar (hover over a message): `React` (button with text, no aria-label), `Reply in thread` (aria-label), `More` (aria-label). Hovering `React` itself shows no picker (it needs a click, not clicked). `More` menu items (menuitem): **Save message, Pin message, Edit message, Delete message** (list only, nothing clicked). Own messages here; for someone else's message the menu may differ (not checked).
- Composer: a rich-text `div[contenteditable]` with placeholder "Message <name>" (a Tiptap-like editor), formatting buttons (title attr): `Bold (Cmd+B)`, `Italic (Cmd+I)`, `Inline code (Cmd+E)`, `Code block (Shift+Cmd+C)`, `Bulleted list`, `Numbered list`. Bottom row buttons (aria-label): `Attach file`, `Attach image`, `Attach video`, `Record voice message`, `Add emoji`, and `Send` (**disabled** while empty). Hint under the box: "Shift + Enter for a new line".
- `Add emoji` opens a picker popover: category tab buttons (recent, smileys, animals, food, activity, travel, objects, symbols, flags), a "Search" input, a skin-tone button, "Frequently used" then "Smileys & People" grids. Closed with Escape.
- Not clicked: any conversation row, Block, Threads/Mentions/Saved rows, React, Reply in thread, Pin/Save/Edit/Delete message, thread buttons, Request, Create room, the Attach/Record buttons (would open a file chooser or microphone prompt), Send.
